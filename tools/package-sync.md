# 공식 패키지 공지 연동

`pkg.html`은 사이트 공통 `ui.css`, `ui.js`, `theme.js`를 사용합니다.
공지 원문을 브라우저에서 직접 가져오지 않고 검증한 로컬 JSON을 읽으므로
공식 사이트의 CORS 설정과 관계없이 표시됩니다.

## 갱신

```sh
python tools/sync-packages.py          # 최근 100건 재확인 + 신규 공지
python tools/sync-packages.py --full   # 전체 목록과 본문 재확인
python -m unittest discover -s tools -p 'test_packages.py'
node tools/test-packages.cjs
```

Python 표준 라이브러리만 사용합니다. `Sync official package notices` 워크플로가
한국 시간 매일 08:30에 실행되며 일요일에는 전체 목록을 재확인합니다.
GitHub 스케줄 실행은 지연될 수 있습니다. Actions에서 수동 실행도 가능합니다.
수집이나 검증이 실패하면 기존 데이터를 유지합니다. 갱신 후 Pages 빌드를
명시적으로 요청하여 봇 커밋도 배포되도록 합니다.

## 데이터와 계산

- 전체 공지의 본문을 검사하고 패키지가 언급된 공지는 모두 원문 링크를 저장합니다.
- 본문에 드래곤 패키지명과 실제 판매 기간이 함께 있는 기록만 자동으로 판매 회차에 반영합니다.
- 공지 작성일을 판매일로 대체하지 않습니다. 종료일이 없는 상시 패키지 변경이나
  보상·드롭·결제 장애 안내를 기간 한정 드래곤 패키지 판매로 계산하지 않습니다.
- 이미지 구성표에서 확인한 정보는 `data/pkg-reviewed.json`에 공지 번호,
  이름, 기간, 가격, 확인 근거를 적습니다. 이미지 정보는 자동으로 추측하지 않습니다.
- 같은 드래곤과 같은 판매 시작일은 한 회차로 합치고 모든 근거 공지를 유지합니다.
- 실제 시작된 서로 다른 판매 회차 사이의 간격으로 중앙값을 구합니다.
  미래 공식 판매 일정은 판매 횟수와 간격에 미리 포함하지 않습니다.
- 예상 복각일은 마지막 판매 시작일 + 중앙값 간격입니다. 1회 판매 항목의
  2년 주기 가정과, 지난 예상일을 미래로 계속 연장하는 방식은 사용하지 않습니다.
- 날짜 계산은 UTC 자정으로 정규화하고 오늘 날짜는 Asia/Seoul 기준으로 계산합니다.

본문이나 이미지에서 이름·날짜를 확인하지 못한 자료도 `관련 공지`에 남습니다.
공식 공지의 수정·삭제, 이미지 교체 시 수동 검토 기록 역시 다시 확인해야 합니다.
